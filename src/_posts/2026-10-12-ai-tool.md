summary: >-
  Rich Hickey argues that LLMs are not tools but automation. A tool, he
  writes, is something you wield: held in the hand, giving control, continuous
  direction and sensory feedback, and building expertise as you use it. LLMs
  offer none of that — you make a request and the model acts on its own, so
  using one to write code is abdicating writing code rather than directing it.
  He likens prompt-writing to gaming a drive-through order, and warns that
  what you skip by abdicating is learning to write, to argue, and to think.
---

Most commenters accept the essay's worry — that abdicating reading and writing
costs you the learning — but split hard on the tool/automation distinction it
rests on. The sharpest objection, from joelgrus, targets the premise that "you
don't direct the action of an LLM": his typical coding session is a continuous
back-and-forth where he rejects bad proposals and sketches the next step, which
sounds a lot like the continuous direction Hickey says is missing. Others attack
the definitional move itself: cultpony notes the Wikipedia tool definition
already excludes machines and computers, so proving LLMs fail it proves little,
while pmbauer answers that quibbling over "tool" misses the real claim — that
automation has costs beyond its immediate utility that users aren't weighing.
fuzzy calls the title badly chosen since AI is not the same as LLMs, and another
reads Hickey as thinking LLMs are only useful for summarization and code
generation. The line commenters liked best is the one about missing "loading
your background mind with fodder for novel ideas."
